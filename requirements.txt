# If you DO enable the openai provider (including free OpenAI-compatible tiers
# such as Groq), also install a current brotli implementation:
#
#   brotlicffi>=1.2.0.0   # or: brotli>=1.2.0
#
# Recent `openai` releases depend on httpx2, which calls the brotli decoder with
# `output_buffer_limit`. Older brotlicffi (<1.2.0.0) has no such parameter, so
# every SUCCESSFUL — i.e. compressed — response raises TypeError and surfaces as
# a misleading "Connection error". Error responses are small and uncompressed,
# so authentication failures still come back normally, which makes the bug look
# like a credentials problem. Observed on 2026-09-01 with openai 3.6.0 +
# httpx2 2.12.0 + brotlicffi 1.1.0.0 on Python 3.13.
#
# Optional: a compliant web-search provider client can be added behind the
# search connector interface (see gsid/ingestion/connectors.py). None is
# required for the RSS-based ingestion path.
